# CPP-016～018 接入口预检与分批方案

2026-11-02。此轮先核查入口、依赖和验证条件；尚未替换游戏业务，也不计入迁移验收。
第一轮15组的实现、14组验收和 CPP09 的真实输入待验收状态保持原记录。

## 已实际检查的内容

复用 CPP09 的原生二进制，在原有隔离工程运行只读 UE 命令行预检。
检查五个项目内容根下577个蓝图的原生父类标签，筛出46个物品/技能定义：
原始 Lyra 中7个物品、37个技能，另有2个此前的测试夹具。没有缺失父类标签。
这证明配置覆盖范围，尚不证明实际对局中的运行可达性。

| 候选 | 配置实况 | 首先要处理的条件 |
| --- | --- | --- |
| CPP-016 初始属性 | 5个物品定义各有1个 SetStats 片段 | 原生内嵌片段不直接承担 Mixin；GameplayTag 作为 TMap 键不能直接转成 Python 字典 |
| CPP-017 物品消耗 | 5个技能定义各有1个 ItemTagStack 消耗对象 | 原生 virtual 入口、ActorInfo、失败标签写回和权威扣除需要窄接口 |
| CPP-018 玩家消耗 | 本次定义扫描未发现 PlayerTagStack 配置 | 先用独立技能夹具验证能力；没有生产消费者时不能签收为生产替换 |

5组对应 Pistol、Rifle、Shotgun，以及 HealthPickup_Unused、NetShooter_PROTO。
后两者保留原本的未使用/原型定位，不因配置存在而算作正常对局验收。
5个消耗配置目前均为弹匣弹药、数量1、无曲线、非命中后才扣费，失败标签为
`Ability.ActivateFail.Cost`。额外分支必须用明确夹具验证，不能假称已有配置覆盖。

| 物品 | 弹匣容量/初始弹药/备用弹药 |
| --- | --- |
| Pistol | 12 / 12 / 48 |
| Rifle | 30 / 30 / 60 |
| Shotgun | 8 / 8 / 16 |
| NetShooter_PROTO | 1 / 1 / 2 |
| HealthPickup_Unused | 1 / 1 / 0 |

以上数值来自原生 CDO 导出。5次直接读取 `TMap<FGameplayTag,int32>` 均出现结构键

本轮不把通用绑定修复混入业务替换，优先增加保持原生迭代顺序的 Tag/Count 类型化数组。

## 建议接入方式

不把现有 `Fragments`、`AdditionalCosts` 中的原生内嵌对象批量换成蓝图子对象。
优先在已有蓝图所有者上建立策略事件：物品定义负责初始化策略，技能实例负责消耗策略。
原生回调必须实际经过该事件，普通 C++ virtual 不会因 Python 存在同名方法而被替换。

CPP-016 的真实入口是库存 `AddEntry(ItemDef)` 创建实例后逐片段调用
`OnInstanceCreated`。从实例取得物品定义，向定义蓝图的策略入口传递目标实例和
类型化属性快照。定义类为 Const，先验证常量 profile 选择器及 const 事件承载，
不直接假设可添加可变 profile 成员。方案尚未编译或运行，需在实施批次先做原型。

CPP-017/018 的真实入口是 `ULyraGameplayAbility` 的 AdditionalCosts 遍历。
保留原签名和 ActorInfo/能力句柄，在原生层解析目标、等级、曲线及原版整数截断，
向技能蓝图传值快照。Python 决定能否支付及消费规则，原生完成合法目标的权威写回。
原生/Python 路由先于任何业务副作用确定；Python 执行中失败后不得再执行原生业务。
原始 C++ 路径作为明确的 NativeFallback 保留。

物品消耗仅在目标有效、数量不足、调用方提供失败标签输出且配置标签有效时加标签。
缺失物品不加标签，PlayerTagStack 原实现也不加失败标签；不能把两者统一改写。
`Super::CheckCost`、遇到首个失败即停止、命中后才扣费、预测及服务器权限继续由原调用链承担。

## 建议分批

1. **CPP10 / CPP-016**：先验证 Const 物品定义的事件承载及类型化属性数组，再替换初始化循环。
   用真实 AddItemDefinition、重复创建、空/零/负数夹具和双客户端验证初始数值及复制。
2. **CPP11 / CPP-017**：在实际武器技能上接入消耗决策。保留此前已验收的蓝图 Python 方法，
   只切换新增 C++ 规则；检查余量不足/相等/充足、失败标签、数量截断、命中条件及只扣一次。
3. **CPP12 / CPP-018**：用独立玩家消耗技能验证 PlayerState、缺失目标、重生/Pawn 更换、
   双客户端及权威写回。账本区分“能力夹具通过”和“生产替换”，后者目前没有配置消费者。

原始配置没有曲线、数量边界及命中限定，因此这些分支单列夹具覆盖。
现有“已有物品实例入包未实现”的原版限制仍单列，不借此扩大初始化迁移范围。

## 工程与回归边界

后续原型与实现使用新的独立工程副本，建议目录为
`.build/LyraValidation/CppGameplayExtended/Stage/Lyra`。
保留 CPP09 的源码、资源和精确二进制，以便解锁后继续真实输入验收；不使用硬链接共享可改文件。
检查复制时的实际磁盘余量，完成独立性和指纹校验后再应用补丁。

只增量编译编译器依赖报告命中的模块/单元。仅改 Python 时复用匹配二进制。
回归现有武器、库存和实际受影响技能；不例行全量构建或 Cook。
